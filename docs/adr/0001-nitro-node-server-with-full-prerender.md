# Nitro node-server with full prerender, self-hosted in Docker

The site leaves GitHub Pages for the owner's own infrastructure, shipped as one Docker image that Coolify builds from the private Forgejo repo; an image from the owner's own registry follows only with the infrastructure's runner server. Every page except the per-language 404 is prerendered, yet the image runs Nitro's `node-server` instead of a plain static server (nginx/Caddy): one Nuxt config then owns every server duty, namely `/health` with the deployed commit, `/mail` as a 302 that keeps the e-mail address out of HTML and JS, the CV PDF download by POST, a Range-capable route for videos, the 301 for trailing slashes and the security headers per path, and it leaves a runtime to hook a self-hosted Strapi into later. Pre-compressed Web builds need no config at all, because Nitro derives `Content-Encoding` and type from the `.br` file name ([ADR-0004](0004-web-builds-as-prebrotli-files-in-same-origin-iframes.md)). We accept a larger image and more memory per static download than a static server would need.

A static export (`nuxt generate`) served by nginx, as the infrastructure plan had assumed, was spiked on 2026-11-15. It handled every server duty and needed far less memory per download. We rejected it because headless-CMS content should appear at runtime without a rebuild (draft preview, instant publishing), and phase 2 needs server endpoints such as a contact form ([Abgleich mit athaeck-infra](../../.scratch/nuxt-portfolio/issues/20-abgleich-infra.md)).
