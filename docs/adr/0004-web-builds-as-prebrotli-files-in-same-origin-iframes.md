# Web builds ship inside the site image as pre-compressed Brotli and run in same-origin iframes

Every Web build (Embed or Game mode) is committed as a Unity "Brotli" release build under `public/builds/<slug>/`, goes into the one site image, and is served by Nitro as literal `.br` files (Nitro sets `Content-Encoding: br` and the original type from the file name). The page shows it in a same-origin `<iframe>`, created only on click and torn down by removing it. We rejected a canvas component with `createUnityInstance`, because cleanup depends on `Quit()` (forum-documented only, leaks with Decompression Fallback), Unity globals and key capture would leak into the SPA, and every engine would need its own component; a subdomain or separate static container, because it needs a second deploy on both paths, a `frame-src` exception in the CSP, and contradicts [ADR-0001](0001-nitro-node-server-with-full-prerender.md); uncompressed builds plus Nitro `compressPublicAssets`, because every site build would recompress them (~1 s per MB) and the image would hold three copies; Git LFS, because builds change rarely and Coolify clones shallow, so LFS saves nothing while adding a failure path over the VPN (Coolify does pull LFS objects, verified later in its source); and a registry artefact, because it adds a push step and registry auth to the build.

## Consequences

- No gzip fallback, and `nuxt dev` (Vite sets no `Content-Encoding`) or plain-HTTP Firefox cannot run a Web build; production is HTTPS-only, where every WebGL 2 browser decodes Brotli. Local integration tests use Chromium against the production container.
- Nitro reads each file fully into memory per request (no streaming, no `Range`), so a visitor who is loading costs about the build's size in server RAM. Hence the budget: 50 MB per Embed, 100 MB for the Game mode, enforced by the build. A larger build leaves the image (registry artefact or streaming static server) rather than raising the budget.
- Headers are set per directory only (`routeRules` cannot match file extensions): `/builds/**` gets its own CSP, so loader needs such as `blob:` never loosen the site's CSP.
- Only release builds are committed; each one stays in Git history for good.
